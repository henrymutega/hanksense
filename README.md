## Overview

Hanksense AI is a full-stack React application that lets educational institutions simulate the end-to-end hiring lifecycle:

1. **Admin** manages lecturers, students, classes, institutions, subscriptions and analytics.
2. **Lecturer** creates classes and sessions, invites students with a class code and reviews student work.
3. **Student** joins a class/session, creates jobs with AI assistance, uploads CVs, screens candidates, schedules interviews, and moves candidates through a hiring pipeline.

The platform is designed for active, classroom-based learning — every student action is scoped to their lecturer's class/session, and lecturers have full visibility into student progress.

## Core Concepts

### Hierarchy

```
Lecturer
  └── Class
        └── Session
              └── Job
                    └── Candidates
                          └── Pipeline
                                └── Hiring Decision / Interview / Offer
```

- **Lecturer** — owns classes and sessions.
- **Class** — a course or cohort. Students join via a class code.
- **Session** — a teaching unit inside a class. Jobs are created under a session.
- **Job** — a role posting generated by AI or manually.
- **Candidate** — an applicant with a parsed CV and match score.
- **Pipeline** — a 7-stage Kanban board (New, Screening, Interview, Offer, Hired, Rejected, Talent Pool).
- **Interview** — scheduled calendar event with real `.ics` invitations.
- **Offer** — final hiring stage before a candidate is marked Hired.

### Roles

| Role | Capabilities |
|------|--------------|
| `admin` | Manage lecturers, students, classes, sessions, institutions, subscriptions, analytics, and ATS workflows. |
| `lecturer` | Create classes/sessions, invite students, view all students and their work, moderate job postings. |
| `student` | Create up to 3 jobs per session, upload CVs, screen candidates, run interviews, manage pipeline. |

## Features

### For Admins
- Auto-initialization: the first registered account.
- Dashboard analytics across all lecturers, classes, sessions, students, jobs and candidates.
- Full RBAC protection.

### For Lecturers
- Class and session management.
- Class code generation for student sign-up.
- Per-class student roster with individual activity metrics.
- Review all student job postings, candidates and pipeline activity.
- Presentation Mode (`/present/:sessionId`) for classroom demos.

### For Students
- Join a class with a validated class code.
- AI Job Copilot: generate detailed, multi-lingual job postings from a prompt.
- CV upload and AI parsing.
- AI-powered candidate-to-job matching.
- 7-stage hiring pipeline with drag-and-drop-style stage transitions.
- Interview scheduling with Google Calendar and `.ics` download.
- Live WebRTC video interview room with screen share, mute, and HD capture.
- Multi-lingual UI (English and Simplified Chinese).

### Shared
- Responsive mobile layout with collapsible sidebar drawer.
- Landing page with scroll animations, parallax effects, and language switching.
- Real-time role-scoped dashboard metrics.
- Forgot/reset password flow.
- Branded loading state.

| Deployment | Vercel, or Cloudflare Workers (via Wrangler) |

## Getting Started

### Prerequisites

- [Bun](https://bun.sh/) (recommended) or Node.js 20+
- A Supabase project (or your own Supabase instance)

### Install

```bash
bun install
```

### Run locally

```bash
bun run dev
```

The dev server starts at `http://localhost:8080`.

### Build

```bash
bun run build
```

### Type-check

```bash
bunx tsgo
```

## Environment Variables

Copy `.env.example` to `.env.local` and fill in the values:

```bash
cp .env.example .env.local
```

### Required

| Variable | Purpose |
|----------|---------|
| `VITE_SUPABASE_URL` | Your Supabase project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Supabase anon/public key |
| `VITE_SUPABASE_PROJECT_ID` | Supabase project ID |

### Optional

| Variable | Purpose |
|----------|---------|
| `OPENAI_API_KEY` | Use OpenAI directly for AI features (local dev or Vercel) |

## Deployment

### Vercel

1. Connect the Git repository to Vercel.
2. Add the following environment variables in the Vercel dashboard:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
   - `VITE_SUPABASE_PROJECT_ID`
   - `OPENAI_API_KEY`

### Cloudflare Workers

The project includes `wrangler.jsonc` for Cloudflare Workers deployment. Make sure all environment variables are bound in Wrangler secrets.

## Database & Migrations

Key tables:

- `profiles` — extended user profiles linked to Supabase Auth.
- `user_roles` — separate role table (admin, lecturer, student).
- `classes` — lecturer-owned classes.
- `class_memberships` — student-to-class enrollment.
- `sessions` — teaching units inside classes.
- `session_jobs` — jobs created under a session.
- `session_candidates` — candidates applied to a session/job.
- `interviews` — scheduled interview events.
- `offers` — offer records.

### Important Rules

- Every new `public` schema table must include `GRANT` statements in the same migration.
- Row Level Security (RLS) is enabled on all user-facing tables.
- Role checks use the `public.has_role(_user_id, _role)` security-definer function.
- Student job creation is capped at 3 posts per session via the `trg_session_jobs_student_cap` trigger.

---

## Authentication & Roles

- Supabase Auth handles email/password and OAuth (Google by default).
- On sign-up, students must provide a valid class code matching a lecturer's class.
- The admin account is auto-granted via a database trigger.
- Protected routes use role gates.
- `/admin` redirects non-admin users.

## AI Copilot

The AI Job Copilot is a 3-step wizard:

1. **Select Class** — student picks an enrolled class.
2. **Select Session** — student picks a session under that class.
3. **Describe Role** — student writes a prompt; localized suggestions appear above.
4. **Generate & Edit** — AI produces a full job posting; student can edit critical fields before posting.

Generated jobs include:
- Title, department, employment type, location, work mode, seniority
- Rich summary, 7–10 responsibilities, 8–12 required skills, 5–8 preferred skills
- Education, experience, certifications
- Salary min/median/max with currency
- Benefits, interview stages
- Bias detection flags with inclusive replacements

Output is localized based on the selected UI language (English or Simplified Chinese), while machine-parseable values remain in English.

## ATS Pipeline

Stages:

1. New
2. Screening
3. Interview
4. Offer
5. Hired
6. Rejected
7. Talent Pool

### Hiring Cascade

When a candidate is marked **Hired**:
- The job status becomes `filled`.
- All other applicants for that job are moved to the **Talent Pool**.
- Their application history, skills, and strengths are preserved for future roles.

## Security Notes

- CSRF middleware is registered in `src/start.ts`.
- Server functions attach the Supabase bearer token via `attachSupabaseAuth`.
- Admin checks are server-side only; never trust client-side storage for roles.
- Secrets are read inside handlers, never at module scope.
- The `/api/public/*` prefix bypasses site auth; webhook/public endpoints must verify callers internally.

## Troubleshooting

### "No AI provider key configured"

You are running locally without `OPENAI_API_KEY`. Either:
- Add `OPENAI_API_KEY` to `.env.local`, or
- Set `AI_PROXY_URL` to your published app and sign in locally.

### Hydration warnings from browser extensions

Extensions like Grammarly may inject attributes into the DOM. These warnings are usually harmless. If you see actual broken content, check the console for a different error.

### Dev server crashes or blank screen

- Ensure all `.env` variables are set.
- Run `bun install` after pulling changes.
- Check `bunx tsgo` for type errors.
- Review the dev server logs for SSR/runtime errors.
